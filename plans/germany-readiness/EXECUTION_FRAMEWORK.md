# Germany Execution Framework

## 1. Purpose

This framework converts the approved Germany strategy into an execution system for the period from 2026 to the Year-2 Decision Gate in approximately 2028.

It is not a fixed 2-year roadmap.
It is a monitoring and evidence system used to preserve PA1 while keeping PA2 as the baseline.

## 2. Current Strategic State

- Baseline: PA2
- Current commitment: continue CTUT through the end of Year 2
- Decision Gate: end of Year 2, approximately 2028
- PA1 remains available and is activated only when the required evidence is sufficient
- Germany Fund at baseline: 0 VND
- Family funding: 0 VND
- Current income: 0 VND
- Game income: unproven
- Required Entry Capital 2028: UNKNOWN

## 3. Core Execution Dimensions

### A. Academic
Track:
- semester results
- GPA trajectory
- failed or outstanding courses
- prerequisite-course risks
- completion of the academic requirements needed for the intended Germany route

Principle:
- Academic performance is protected.
- Do not create an arbitrary GPA hard cut-off unless the actual target route requires it.
- A game or income target cannot justify sacrificing critical CTUT progress.

### B. Language
Track separately:
- English proficiency / IELTS
- German proficiency
- certificate status
- test date
- validity and acceptance requirements for the intended application route

Principle:
- Do not take a high-cost certificate too early solely to “check a box”.
- Verify the certificate timing and acceptance rules when the target application window becomes clear.

### C. Germany Admission and Legal Readiness
Track:
- HSRW admission requirements
- APS requirements applicable to the user's actual academic status
- Uni-assist requirements and fees
- proof-of-funds rules
- visa requirements
- document requirements
- timelines and dependencies
- recognition / credit-transfer questions

Principle:
- Current information is research input, not a permanent guarantee for 2028.
- Re-verify time-sensitive requirements close to application.

### D. Finance
Track:
- Total Liquid Assets
- Emergency Fund
- Germany Fund
- Required Entry Capital
- Remaining Finance Gap
- money that is committed and therefore not actually available

Definitions:

Germany Fund =
cash intentionally reserved for Germany and actually liquid.

Finance Gap =
Required Entry Capital 2028 - Germany Fund actually available at the Decision Gate.

Proof-of-funds must not be double-counted as an additional post-arrival living expense.

### E. Income
Track candidate income engines separately:
- Game development
- Freelance / IT work
- Other legitimate income opportunities

Game income model:

Gross Revenue
→ Platform Deductions
→ Applicable Taxes / Withholding
→ Payment / FX Costs
→ Direct Game Costs
→ Net Game Cash Received
→ Personal Living Costs
→ Emergency Fund
→ Germany Fund

Only cleared cash that has actually been received counts toward Germany Fund.

Do not treat projected revenue as funding.

### F. Career / Portfolio
Track:
- software engineering fundamentals
- programming capability
- completed projects
- portfolio quality
- relevant internship / work experience
- employability outside game development

Principle:
- Game projects may serve both income and portfolio goals, but do not assume game work automatically satisfies general Software Engineering hiring requirements.

### G. Time / Execution Capacity
Track the combined load of:
- CTUT
- game development
- income work
- English
- German
- Germany research/application preparation

Principle:
- Time allocation must protect the highest-value irreversible assets first.
- Avoid maintaining parallel goals indefinitely without evidence of progress.

## 4. Dependency Model

Typical dependencies to verify rather than assume:

CTUT academic progress
→ required transcript / academic evidence
→ APS applicability and processing
→ application eligibility
→ HSRW / Uni-assist application
→ admission
→ proof-of-funds preparation
→ visa application
→ departure

The exact sequence must be re-verified against the requirements that apply at the time of application.

Financial dependency:

Cleared Cash
→ transferable / documentable funds
→ valid proof-of-funds arrangement
→ visa readiness

Do not count revenue that is still pending payout.

## 5. Decision Reversibility

### Reversible / broadly reusable
- improving GPA
- improving English
- learning German
- programming practice
- building software projects
- building a portfolio
- testing income ideas

### Potentially irreversible or costly to reverse
- sacrificing required CTUT coursework
- delaying graduation-critical prerequisites
- committing large non-refundable amounts before the route is sufficiently verified
- transferring large sums before the applicable proof-of-funds route is confirmed

Framework rule:
Prefer reversible actions while information is uncertain.
Delay costly irreversible commitments until the relevant conditions are verified.

## 6. Checkpoint System

### 2026-09-30 — Baseline
Record:
- Germany Fund
- Total Liquid Assets
- current income
- academic status
- language status
- Germany-readiness status
- current income-engine evidence

### 2026-12-31 — Early Evidence
Ask:
- Has any income engine produced real evidence?
- Is CTUT progress on track?
- Are there any early academic risks?
- Which Germany requirements have been verified?

### 2027-06-30 — Midpoint Review
Ask:
- Has game or another income engine produced actual cleared cash?
- Is there evidence of repeatability?
- Is the income path consuming too much academic capacity?
- What is the current Germany Fund and Finance Gap?
- Which requirements are still unknown?

This is a review checkpoint, not an automatic PA1→PA2 trigger.

### 2027-12-31 — Pre-Decision Review
Ask:
- Is Germany Fund materially growing?
- Is income repeatable enough to be part of the decision model?
- Is academic progress safe?
- Is language progress sufficient for the intended route?
- What time-sensitive Germany requirements need re-verification?

### 2028-03-31 — Decision Preparation
Update:
- current proof-of-funds requirement
- realistic entry-cost estimate
- current Germany Fund
- required liquidity buffer
- current admission / APS / visa readiness
- current language evidence
- value of continuing CTUT Years 3–4

### Decision Gate — approximately 2028
Compare PA1 and PA2 using actual evidence.

No automatic branch change is triggered by one metric alone.

## 7. Income Evidence Ladder

- Stage 0: no commercial evidence
- Stage 1: completed product with paying users
- Stage 2: actual payout received
- Stage 3: repeated revenue evidence across products or cycles
- Stage 4: meaningful contribution to Germany Fund
- Stage 5: Germany Fund is actually usable for the Decision Gate

The ladder measures evidence maturity.
It does not predict future success.

## 8. Failure / Pivot Signals

Use evidence-based review rather than arbitrary percentage targets.

### Academic protection signal
If income work begins materially damaging critical CTUT progress, reduce or pause the income activity.

### Income viability signal
If repeated real-world tests fail to produce economically meaningful net cash, reassess the income engine instead of assuming future success.

### Financial feasibility signal
If the Germany Fund remains materially below the required entry capital as the Decision Gate approaches, quantify the remaining gap and reassess PA1 feasibility.

### Information readiness signal
If a required admission, APS, language, financial, or visa condition remains unknown close to the Decision Gate, treat it as unresolved risk rather than assuming it will work.

These signals do not automatically select PA2. They provide evidence for the Decision Gate.

## 9. Information Timing

### Verify now
- HSRW target-program structure and admission logic
- current APS framework relevant to the user's route
- current Anabin / institutional recognition information where relevant
- CTUT transcript / document issuance process
- candidate income-engine feasibility
- current language requirements relevant to the target program

### Re-verify closer to application
- 2028 proof-of-funds amount
- visa and VFS procedures
- exact application deadlines
- current HSRW fees
- housing and Kaution
- insurance costs
- exchange-rate assumptions
- provider-specific financial-account fees
- exact program rules in the application year

## 10. Information That Should Not Be Hard-Coded

Do not hard-code as universal rules without route-specific evidence:
- a fixed 2028 proof-of-funds amount
- a fixed 500M VND target
- a fixed GPA cut-off
- a fixed 45% / 80% cash-progress target
- a universal game tax rate
- a universal payout delay across platforms
- a universal visa deadline month
- a universal 3–6 month inability to work after arrival

## 11. Execution Rule

The framework exists to answer:

1. What is true now?
2. What is unknown?
3. What can be verified?
4. What evidence has been created?
5. What irreversible decisions should still be avoided?
6. Is the PA1 option becoming more or less feasible as real data accumulates?

Execution should therefore proceed from:
Baseline
→ Verify
→ Act
→ Measure
→ Red-team
→ Adjust
→ Reassess at checkpoint

rather than from a fixed 2-year schedule.
